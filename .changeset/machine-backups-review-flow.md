Merging across machines is now something you can see and steer. The sync channel gained two reads: `backups` walks the branch history newest first and names each commit by the Pack manifest it carries — time, the machine that published it, the push time and the component summary — so one shared branch reads as the list of every machine's backups, and `diff` compares the local payload with the branch payload entry by entry, reporting both sides' export time, entry count and machine, the entries only here, the entries only there, how many they share and the tombstones the branch carries. Entries are identified by target and content, so the same memory counts as one entry wherever it was written; both lists are bounded and `truncated` says a side held more. A removal is reported only when this installation has not carried it out yet: the branch keeps every removal either side ever recorded, so a removal this installation already applied, or has since written over, is not outstanding. Publishing records the deletions it is about to publish **before** it folds the branch in, because folding the branch in restores the entries just deleted and the export that follows can no longer see that they went away. Neither endpoint needs `writeEnabled`: gating a read behind write access would hide exactly the evidence an operator needs before deciding whether to write. Reconciliation now takes the reviewer's own words as `guidance`, which shapes the plan and never widens what an operation may contain, and its evidence also carries what the branch holds and this installation does not, plus the opinions already recorded on pending proposals. `apply` accepts an `operations` array of plan positions, so an accepted proposal can be applied in part; an index the plan does not hold is refused rather than silently dropped, because dropping it would let a caller believe the whole review was applied. In the page, **Backups** lists that history, **Check remote** shows the entry-level difference after the component preview, reconciliation has a **What to accomplish** field, and an accepted proposal shows a checkbox per operation with **All** and **None**.

跨设备合并现在既能看见也能掌控。同步通道新增两个只读端点：`backups` 由新到旧遍历分支历史，并用该提交携带的 Pack manifest 说明每次备份——时间、发布它的机器、推送时间与组件摘要——因此一条共享分支读起来就是各台设备的备份清单；`diff` 逐条比较本地载荷与分支载荷，报告两侧的导出时间、条目数与机器，只在本机的条目、只在远端的条目、共有条数，以及分支携带的墓碑。条目身份是「目标层 + 内容」，因此同一条记忆无论在哪台机器写入都算一条；两份列表都有上限，`truncated` 表示某一侧还有更多。只有本机尚未执行的删除才会被报告：分支保留双方记录过的每一条删除，因此本机已经执行过、或此后又写回同内容的删除都不算未决。推送会**先**记录本次要发布的删除、再并入分支——因为并入分支会把刚删掉的条目恢复回来，随后的导出就看不出它们曾经消失。两个端点都不要求 `writeEnabled`：把读操作挡在写权限后面，恰好会藏起操作者在决定是否写入之前最需要的证据。整理记忆现在接受审查者自己的话作为 `guidance`：它塑造计划，但绝不放宽单条操作允许包含什么；证据中还会带上分支持有而本机没有的条目，以及待审查建议上已记录的意见。`apply` 接受 `operations` 位置数组，因此已接受的建议可以只执行一部分；计划中不存在的位置会被拒绝而不是静默丢弃——静默丢弃会让调用者以为整份审查都已应用。页面上，**Backups** 列出这份历史，**检查远端**在组件预览之后显示逐条记忆差异，整理记忆新增**整理要求**输入框，已接受的建议为每条操作显示复选框并带**全选**/**全不选**。
