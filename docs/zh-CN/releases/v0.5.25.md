# v0.5.25：没有记忆空间也能工作的记忆，以及保存位置的选择

**简体中文** | [English](../../en/releases/v0.5.25.md)

本补丁版本发布七项修复：[#343](https://github.com/omdsh-dev/dsh-mnemon/pull/343)、[#344](https://github.com/omdsh-dev/dsh-mnemon/pull/344)、[#345](https://github.com/omdsh-dev/dsh-mnemon/pull/345)、[#346](https://github.com/omdsh-dev/dsh-mnemon/pull/346)、[#347](https://github.com/omdsh-dev/dsh-mnemon/pull/347)、[#348](https://github.com/omdsh-dev/dsh-mnemon/pull/348) 与 [#349](https://github.com/omdsh-dev/dsh-mnemon/pull/349)。

- **没有记忆空间时，记忆照常工作**（[#345](https://github.com/omdsh-dev/dsh-mnemon/pull/345)）。工作记忆（MEMORY.md）写满、又没有任何记忆空间能接收归档时，每次写入都会被拒绝。记忆空间层关闭、没有安装或就绪的 Provider、没有激活的空间，都会出现这种情况。现在运行时记忆会把整理时移出的条目逐字追加到 `runtime/archived/` 中的本地存档，然后完成整理和这次写入。项目档案也按同样方式在本地归档，并保留原文。如果有空间可以接收归档、只是当前这一轮无法写入，写入仍像以前一样被拒绝，所有条目原样保留。Mnemon Pack 会带上本地存档。
- **保存到记忆时可以选择位置**（[#349](https://github.com/omdsh-dev/dsh-mnemon/pull/349)）。回复上的**保存到记忆**现在提供**保存到**选项。任务 Agent 可以写入时，默认仍是**由 Agent 决定**。**工作记忆（MEMORY.md）**、**用户画像（USER.md）**和每个激活的记忆空间会立即写入，走的是与各自页面相同的写入路径。没有任务 Agent 或没有记忆空间 Provider 时，对话框默认选中工作记忆，而不是一个注定失败的提交。
- **修改后的候选可以再次提交**（[#343](https://github.com/omdsh-dev/dsh-mnemon/pull/343)）。显示回执后，修改候选再提交会报 `idempotency key was already used for different content`。现在修改后的文本会作为新的候选交给任务 Agent；原样再提交仍返回原来的回执，不会重复写入。
- **按 id 遗忘记忆**（[#346](https://github.com/omdsh-dev/dsh-mnemon/pull/346)）。只要当前 View 没有召回过这个 id，`mnemon_forget` 和 `/mnemon forget <ID>` 都会失败。现在记忆空间会在 View 可读的空间中，通过 Provider 新增的可选方法 `get(body, id)` 查找这个 id，只有恰好一个空间持有它时才执行。链接与相关记忆遍历也按同样方式解析 id。Mnemon Native 用只读的 `mnemon show` 实现 `get`。
- **归档到 Mnemon Native 不再因重复条目失败**（[#347](https://github.com/omdsh-dev/dsh-mnemon/pull/347)）。MEMORY.md 写满后归档的条目如果空间里已经有一模一样的一条，Host 会再用一次排序召回去核对。一次召回慢了或排名靠后，整个归档就会失败，之后每次重试也一样。现在，带有已存记忆 id 和原文的跳过回执本身就是证据。仍需检索核对时，错误信息会说明是检索不可用，还是没有找到原文副本；Mnemon CLI 超时也会写明是哪条命令。
- **只是查看，不再算作使用**（[#348](https://github.com/omdsh-dev/dsh-mnemon/pull/348)）。记忆空间的**直接检索**和实体页的**查找相关记忆**现在读取快照，不再给 Mnemon Native 的操作日志添加记录，也不增加访问计数；Mnemon 的留存规则会参考这些计数。Agent 召回、`/mnemon recall` 和 **Agent 查询**仍像以前一样记录使用。
- **在其他设置外壳中显示组件设置**（[#344](https://github.com/omdsh-dev/dsh-mnemon/pull/344)）。外壳不经过 DSH 的 slot 渲染器绘制 dsh-mnemon 配置时，运行时记忆和记忆空间没有齿轮按钮，分层策略页面也没有后台任务。现在配置页在拿不到 `renderSlot` 时会自行渲染这些设置。DSH 自带的插件页不变。

## 升级与兼容性

从 v0.5.22 可使用**记忆系统 → 状态 → 检查版本 → 更新**，完成后重启 DSH。命令行安装或更新到精确版本：

```sh
dsh plugin --profile web add dsh-mnemon@0.5.25
```

安装后重启正在运行的 DSH；新安装可在插件页选择**立即启用**。明确指定版本可避免 pnpm 发布后 24 小时的等待窗口选中较早的版本。较早的桌面安装升级方式见[兼容性与升级](../reference/compatibility.md)。

支持的宿主为 **DSH 0.2.0-rc.2**（npm `latest` 与 `next`）；完整 Profile 使用 Node `^22.19.0 || >=24.0.0`。无需迁移已有记忆。`runtime/archived/` 只在写入本地存档时出现。没有实现 `get` 的第三方记忆空间 Provider 照常可用：它们查不到的 id 仍像以前一样通过 View 已有的证据处理。不新增 Starter SDK 导出，插件 peer 下限不变。
